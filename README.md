# Unsloth Studio flake

The default `unsloth-studio` package retains upstream socket behavior. Consumers that bind to `::` and need IPv4 clients to reach the same listener can select `unsloth-studio-dual-stack` instead. Both are available through `packages.<system>` and through `overlays.default` as `python3.pkgs.unsloth-studio` and `python3.pkgs.unsloth-studio-dual-stack`. The overlay builds both variants with the caller's Python, nixpkgs and CUDA configuration.

The opt-in variant applies `patches/dual-stack-ipv6.patch` to the pinned upstream source before packaging. Importing `studio` suppresses truthy `IPV6_V6ONLY` setsockopt calls for that Python process, including asyncio's default IPv6-only listener setting. It preserves the previous homelab behavior: it does not change the system's initial socket default, and it does not affect other socket options or explicit zero values. Deployments require the normal Linux `net.ipv6.bindv6only=0` default. This process-wide behavior is why the package remains opt-in.

Run `nix build .#checks.x86_64-linux.dual-stack --no-link` for the focused regression. It loads the actual `python -m studio.backend.run --help` entrypoint from both sources, verifies the service arguments and setsockopt behavior, and opens real asyncio listeners to exchange data over IPv6 and IPv4 loopback. Stock remains IPv6-only; the variant accepts both address families. This source-level check uses Python and structlog and does not load the GPU application, build the frontend or validate inference. Full runtime package and consuming machine builds remain separate integration checks.

The PR/main workflow runs the focused regression. `update-version` also runs it after the shared flake-lib updater on every invocation, including unchanged pins and each version branch visited by `update-branches`. Failure prevents that branch from being committed or published. Upstream version, source hash and sibling selections remain in `pin.nix`; patch maintenance belongs alongside that pin here.
