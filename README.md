# Unsloth Studio flake

The default `unsloth-studio` package includes the IPv6 dual-stack patch. It is available through `packages.<system>.unsloth-studio`, `packages.<system>.default`, and through `overlays.default` as `python3.pkgs.unsloth-studio`. The overlay uses the caller's Python, nixpkgs and CUDA configuration.

The package applies `patches/dual-stack-ipv6.patch` to the pinned upstream source before packaging. Importing `studio` suppresses truthy `IPV6_V6ONLY` setsockopt calls for that Python process, including asyncio's default IPv6-only listener setting. It preserves the previous homelab behavior: it does not change the system's initial socket default, and it does not affect other socket options or explicit zero values. Deployments require the normal Linux `net.ipv6.bindv6only=0` default.

Run `nix build .#checks.x86_64-linux.dual-stack --no-link` for the focused regression. It loads the actual `python -m studio.backend.run --help` entrypoint from the patched package source and the original upstream source used as a test baseline, verifies the service arguments and setsockopt behavior, and opens real asyncio listeners to exchange data over IPv6 and IPv4 loopback. The upstream baseline remains IPv6-only; the patched package accepts both address families. This source-level check uses Python and structlog and does not load the GPU application, build the frontend or validate inference. Full runtime package and consuming machine builds remain separate integration checks.

The PR/main workflow runs the focused regression. `update-version` also runs it after the shared flake-lib updater on every invocation, including unchanged pins and each version branch visited by `update-branches`. Failure prevents that branch from being committed or published. Upstream version, source hash and sibling selections remain in `pin.nix`; patch maintenance belongs alongside that pin here.
